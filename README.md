# Watchdog

SAU System Programming Term Project 1.

Watchdog is a Linux process supervisor that monitors worker processes,
restarts them after unexpected termination, and logs process events.
It supports status reports via `SIGUSR1` and controlled shutdown via
`SIGTERM` or `Ctrl+C`.

| Contributor | Module |
| --- | --- |
| Student 1 | Main program, signal handling, and graceful shutdown |
| Student 2 | Child process management, restart limit, and periodic checks |
| Student 3 | Logging, status reporting, Makefile, tests, and documentation |

Each student commits their own implementation from their own GitHub account.

## Build

Use Linux or WSL with a C11-compatible compiler and Make. From the
repository root, run:

```sh
make
```

This builds `./watchdog` and `./workers/worker`. Run `make clean` to remove
the generated binaries and build files.

## Usage

From the repository root, start the watchdog with both workers in normal mode:

```sh
WATCHDOG_WORKER_MODES=normal,normal ./watchdog
```

Press `Ctrl+C` for a controlled shutdown. The watchdog writes events to
`watchdog.log` in the current working directory.

To try signal-based status reporting, start the watchdog in the background
and save its PID:

```sh
WATCHDOG_WORKER_MODES=normal,normal ./watchdog &
watchdog_pid=$!
```

Once the workers have started, run `kill -USR1 "$watchdog_pid"` in the same
shell to request a status report. After the report appears, run
`kill -TERM "$watchdog_pid"` to request shutdown and
`wait "$watchdog_pid"` to wait for it to finish.

## Tests

On Linux/WSL, run:

```sh
make -B all
make test
```

The integration script runs seven scenarios: normal operation, normal exit
(`exit0:1,normal`), unexpected termination and restart, exactly three restarts
and the restart limit, SIGUSR1 status reports, controlled shutdown, and log
format/event validation. Controlled shutdown checks SIGTERM and Ctrl+C
separately. Ctrl+C is generated by writing ETX to a controlling pseudo-terminal
created with util-linux `script`, exercising the terminal's foreground-group
SIGINT behavior.

Tests require Bash, a C compiler, make, util-linux (`setsid`, `script`),
and standard Linux tools including ps, awk, grep and sed. Each scenario uses
a separate temporary directory (the two shutdown variants use subdirectories).
A scenario prints PASS only after all assertions succeed. Any failed scenario
makes `make test` fail. The remaining scenarios still run. Output includes
the retained log directory, with `watchdog.log`, `console.txt`, and a terminal
transcript for the Ctrl+C case.

### Test Results

The integration branch built successfully on WSL and all seven test
scenarios passed, including both controlled-shutdown variants.
